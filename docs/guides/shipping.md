# Shipping

**ship** in the header is the changelog desk. Watch a GitHub repo. When it tags a release, gitpo.st drafts the product post so writing stays tied to shipping.

## Watch a repo

On `/changelog`, paste `owner/repo` or a `github.com/owner/repo` URL and **Watch**.

The **watching** list shows each repo and the last tag seen. **Unwatch** drops it.

You must be signed in.

## Or paste a release

If you already have a release URL, paste it and **Suggest**. That creates a suggested post without waiting for the next tag.

## Write the post

**suggested posts** lists new tags: name, tag, repo, and a link to the release.

- **Write post** turns the hint into a private draft and opens compose in **story** mode, with the release attached.
- **Dismiss** drops that suggestion.

From there, edit the subject and narrative, then commit like any other story. See [Posting](posting.md).

A new tag can also land in your **inbox** as a **release** row, with a link back here.

## Tips

- Watch the repos you actually ship. The point is a prompt to write, not a firehose.
- The draft is yours until you commit. Change the subject so it reads as a log entry, not only a tag name.
- Link extra issues or PRs on the published object with **Link issue / PR** if the release is one of several objects in the story.
